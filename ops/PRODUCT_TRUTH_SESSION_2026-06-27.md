## THE GOAL (as currently stated — to be sharpened)
Answer LATER the questions people today answer by attaching a LIVE image to ChatGPT
("how much soya is this?") — from PASSIVE capture, with NO deliberate framing.

## THE CENTRAL TENSION — v1 (Chief's opening claim) — REJECTED by founder
Claim was: passive capture loses the human's deliberate FRAMING, so no single frame is ever good
enough. **Founder rejected this:** the answer is NOT meant to come from one frame at query time. It
comes from a PERSISTENT, COMPOUNDING memory the brain builds across an object's whole lifecycle.
Framing-loss only bites if you need the answer from one moment; the product explicitly doesn't.

## THE PRODUCT (founder, crisp — stop repackaging it)
**Continuous rich context.** Vision = the TEMPORARY thing to get right now. Memory = the PERMANENT
thing that evolves/compounds forever. It is BOTH, not either. The bookkeeping IS the idea, not a
clever alternative. The brain keeps a running ledger of entity state across time; helpers just hand
fragments to the back; ANY later question reconstructs from accumulated context.
- Example (soya): order on Amazon (read "500g" off screen) → package arrives → opened → decanted →
  scooped into bowl → plated. No single moment is a clean framed shot; the brain triangulates the
  truth from the whole chain. Redundancy across time is the antidote to framing-loss.
- Example (cooking/macros): recorded the cook, forgot to photo ingredients + portion. If memory
  holds all ingredients (from the cook) AND sees the portion on the plate → calories/protein.

## THE CENTRAL TENSION — v2 (the real candidate impossibility)
The ledger's spine is CROSS-CONTEXT, CROSS-TIME identity ("this powder = the soya I bought"),
across representations that share NO coordinate frame (screen vs package vs jar vs bowl vs plate).
- The validated win this session (world-coordinate counting) is SINGLE-VISIT binding — easy half.
  It does NOT generalize to lifecycle binding (the hard half), which is semantic/episodic. Unbuilt.
  (North Star §5.4 admits cross-time identity is unsolved.)
- Why it's the nuke crux: a mis-THREAD fails SILENTLY. Every observation is real; only the linkage
  is wrong → refusal gates (which watch perception, not linkage) never fire → confident wrong
  answer. A corrupted ledger breaks the honesty moat from the inside, where the guards are blind.
- Feasibility reduces to: can cross-context identity be conservative enough to REFUSE to thread when
  unsure, yet thread often enough that the ledger isn't empty. Unsolved for open-world objects.

## OPEN FORK (on the table, founder to weigh in dynamically)
How much of the lifecycle thread is carried by CHEAP HARD ANCHORS (literal "500g" on the order,
label/receipt text — near-perfect, machine-readable) vs VISION stitching the gaps?
- Anchors = skeleton, vision = interpolation  → dramatically more tractable.
- Vision must carry the thread itself          → likely "not with what exists."

## TWO MACHINES (the black-box realization — founder's retrieval answer)
The brain is an LLM: prompted, not programmed; same prompt → different output. So we build TWO things:
1. DETERMINISTIC SUBSTRATE (engineer + test hard): capture, the cross-linked store, retrieval TOOLS

2. NONDETERMINISTIC REASONER (prompt + MEASURE statistically, never assert): the LLM that drives the

Founder can't (nobody can) specify the brain's internals — that's inherent. Founder defines BEHAVIOR
and tries to BREAK it. → System must be GENERAL from day one (adversarial use), NO chosen first slice.

## CONSISTENCY → RESOLVED as ADAPTIVE EFFORT + PRECISE RETRIEVAL
Founder rejected "commit conclusions" (correctly — it's the ChatGPT-memory failure: stored
conclusions reused WITHOUT re-thinking → errors calcify, richer context makes it dumber). Insight:
that's a RETRIEVAL-PRECISION problem, not a memory problem. Big undifferentiated pile → model "uses"
it without thinking; minimal sufficient slice → model thinks. So:
- Antidote to variance = PRECISE retrieval (right 5 notes, not nearest 500), NOT more sampling.
- Effort is PER-QUESTION: "where are my keys" = one cheap precise pass, fast; "protein today"
  (quantitative/contested) = deeper work. Don't pick a global policy.
- Floor = single precise pass + show honest range; ESCALATE only when the brain flags itself
  uncertain/contested. Don't let it get stuck self-deliberating on easy Qs (multi-agent over-reason
  = worse, like saved-memory bloat).

# THE BLUEPRINT — TRACE v2 (greenfield spine for the WOW demo)
*Two machines: a DETERMINISTIC substrate (engineer+test) + a NONDETERMINISTIC reasoner (prompt+
measure). Build the substrate hard; manage the brain's variance at the seam.*

## Layer 0 — CAPTURE (harden + salvage)
- Always-on, multi-source: phone camera + phone screen + Mac screen + audio.
- DECOUPLE capture rate from perception (kills the 0.44fps bug): stream/full-video buffer → frame
  supplier picks sharp keyframes (salvage frame_quality blur gate) → Mac perceives → RAW DELETED.
- Mac-side perception: GroundingDINO + per-crop VLM + OCR + ASR + pose/depth (force CPU where MPS
  crashes). Salvage instance_perceive + helpers as TOOLS.
- Output: TYPED OBSERVATIONS w/ provenance (source, t, place, pose) → append-only log.

## Layer 1 — STORE (build new — THE SPINE, was ~5%)
- Append-only observation log, NEVER delete (salvage sqlite_eventlog).
- CROSS-LINKED GRAPH: nodes=observations/entities; edges=same-time / same-place / same-entity
  (semantic) / succession. The links ARE the asset.
- VECTOR INDEX for PRECISE retrieval (minimal sufficient slice, not biggest pile — the anti-bloat fix).
- Flagged ABSTRACTIONS store (derived, separate from observed).

## Layer 2 — SLEEP (build new)
- Nightly, reconsiderable: dedup → author links (mechanical + semantic + LLM-authored groupings) →
  write FLAGGED abstractions ('soya ~2x/week'). Never hardens weak links.

## Layer 3 — RETRIEVE + REASON (build new — THE BRAIN, was ~2%)
- Agentic loop: frontier-TEXT reasoner with TOOLS (search store / follow links / fetch context /
  read abstractions). Multi-hop traversal (Amazon→box→jar→bowl→plate).
- SELF-SCALING effort: one cheap PRECISE pass; escalate (more hops/sampling) ONLY when the brain
  flags itself uncertain/contested. Fast on easy, careful on hard.
- Output contract: answer + EVIDENCE CHAIN + calibrated confidence + honest refusal at capture's edge.

## Layer 4 — MEASURE (build new)
- annotate-as-you-live: founder logs (Q, true answer, when) → score pass-rate over reruns +
  hallucination. GATE: ≥75% answered, <10% confident-wrong (<10% is non-negotiable).
