# THE ANTI-TUNNEL LEASH
*The Chief's self-check. Run it every cycle — before declaring work "done" AND before choosing
what to build next. Worker proposes; this Critic can VETO and delete the path (Rule 3, one-way
valve: info flows Critic → Worker, never the reverse). Invoke anytime: "run the leash."*

## Why this exists (the failure record — be honest about it)
The Chief has drifted BOTH ways in one session:
- **Too narrow:** polished the OCR-consensus corner and called it the product.
- **Too broad (the equal+opposite trap):** built an "understanding" layer and declared it *verified*
  on ONE question over ONE 18-record capture. That is a demo, not proof — the same fake-number
  trap as "RAS 85.7."
Both are tunnel vision. The leash catches both, plus the honesty flaw underneath them: **declaring
"done/works" on cherry-picked evidence.**

## GOAL LOCK — there are only TWO deliverables
1. A **flawless 3-minute investor demo** that makes the *Context → Prompt → Answer* paradigm undeniable.
2. A **trustworthy, honest number** on real held-out use (real n, lies near zero).
Everything else is downstream noise. If a task serves neither *this cycle* → don't start it.

## THE 7 QUESTIONS (answer before "done" and before "next")
1. **GOAL** — Which of the two deliverables does this move *this cycle*? Neither → **STOP**.
2. **OVER-NARROW** — Am I polishing one channel/corner and calling it the product? *(OCR trap)*
3. **OVER-BROAD** — Is this a layer that *feels* like vision but ships no demo and no number? Does
   RULE 4 say cut it? *(architecture-astronomy trap)*
4. **VERIFIED?** — Real evidence: adversarial, n>1, honesty-guards actually firing on REAL data — or
   am I declaring victory on ONE demo? *(fake-number trap — the recurring flaw)*
5. **WIRED?** — Integrated into the engine + a surface someone actually touches — or a dead module?
   *(scrub_pii trap)*
6. **FOUNDER PRIORITY** — Is this the founder's #1 right now, or what's locally compelling to me?
   Unsure → surface and ask, don't barrel.
7. **HONEST?** — Is every claim I'll make literally true + provable? Any "roadmap / by-design"
   dressed as "done"?

## STRUCTURAL ENFORCEMENT (so it's "always", not "when I remember")
- Every `[STATE_MANIFEST]` MUST carry a `LEASH:` line answering #1 (goal), #4 (verified *how*),
  #6 (founder-#1? y/n). **No manifest without a leash line.**
- A fresh instance runs this file before its first build (pointer in memory + handoff).

## HONEST DEFAULTS (the tiebreakers)
- **One demo ≠ verified.** Verify before you build on top of it.
- Torn between "narrow" and "broad"? Tiebreaker = whichever produces a **VERIFIED, WIRED,
  DEMONSTRABLE** increment toward the two deliverables.
- **Deferring is good.** Optimization (faster/cleaner/more-robust) is NOT paradigm work until the
  thing it optimizes is *proven* to be the bottleneck.
- When the founder course-corrects, the lesson is rarely "do the opposite" — it's "you lost the
  goal lock." Re-read the two deliverables before re-planning.
